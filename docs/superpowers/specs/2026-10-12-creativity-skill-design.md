# 창의성 스킬·하네스 설계 (하위 프로젝트 2)

- 날짜: 2026-10-12
- 상태: 사용자 검토 대기
- 선행: 벤치마크 설계 `2026-10-12-benchmark-design.md`, 같은 설정 비교 점검 통과(`docs/results/2026-10-12-aa-dev.md`)

## 1. 목적과 성공 기준

**목적.** 코딩 에이전트의 창의성을 올리는 두 가지 도구를 만들고, 벤치마크로 어느 쪽이 얼마나 효과가 있는지 비교해 공개한다.

1. **생각 절차 스킬**(`creative-thinking`): 창의적인 작업에서 따르는 지침 한 장. 비용 증가가 거의 없다.
2. **후보 경쟁 하네스**(`creative-tournament`): 하위 에이전트 여럿이 서로 다른 관점으로 완성본을 만들고, 심사 에이전트가 가장 독창적인 것을 고른다. 비용이 몇 배 든다.

**성공 기준(사용자 결정).** 시험 문제(holdout) 전체에서 스킬 없는 에이전트와 비교한 지수의 95% 오차 범위 **아래쪽 끝이 50을 넘으면** 성공. 각 도구를 따로 판정한다.

**함께 보고하는 것(실패 판정은 아님).** 설정별 평균 소요 시간, 문제 해결 축 테스트 통과율. 통과율이 기준보다 떨어지면 보고서에 명시한다.

## 2. 벤치마크 확장

### 2.1 시험 문제 48개

- 축마다 시험 문제를 4개에서 16개로 늘린다(새로 12개씩, 모두 36개). 연습 문제(dev)는 축마다 4개 그대로.
- 형식과 원칙은 기존 태스크와 같다. 문제 해결 축은 각 태스크에 `starter/`, `tests/`(규칙 검사 + 동작 검사 + 동적 실행 금지), `reference.py`, `obvious.py`를 둔다. 기존 자동 점검(정답 통과, 시작 파일·뻔한 풀이·exec 우회 실패)을 그대로 통과해야 한다.
- 개수 점검 테스트를 축별 dev 4 + holdout 16으로 바꾼다.

### 2.2 누수 방지: 시험 문제는 별도 에이전트가 만든다

- 새 시험 문제 36개는 별도 하위 에이전트가 만든다. 스킬·하네스를 만드는 쪽(이 세션)은 시험 문제의 내용을 열람하지 않는다. 확인은 자동 점검 통과 여부와 개수, 그리고 형식 검사로만 한다.
- 만드는 에이전트에게는 기존 연습 문제만 예시로 주고, 연습 문제와 겹치지 않는 주제를 요구한다.
- 기존 시험 문제 12개는 이미 이 세션에서 작성했다. 이것은 알려진 한계로 기록한다(새 36개가 다수다).

### 2.3 보고서·명령 보강

- 보고서 실행 표에 설정별 **평균 소요 시간(초)** 열을 더한다.
- `aci score`에 `--a`, `--b` 옵션을 더한다. 한 실행 폴더에 세 설정(스킬 없음, 스킬, 하네스)을 돌리고, 짝마다 따로 채점·점수를 낼 수 있게 한다. 지정하지 않으면 지금처럼 `judge.json`의 짝을 쓴다.

## 3. 플러그인 구조

한 설정이 한 도구만 불러와야 비교가 깨끗하다. 그래서 도구마다 별도 플러그인으로 나누고, 저장소 루트는 플러그인 목록(마켓플레이스)이 된다.

```
.claude-plugin/marketplace.json        # 두 플러그인을 나열
plugins/
  creative-thinking/
    .claude-plugin/plugin.json
    skills/creative-thinking/SKILL.md
  creative-tournament/
    .claude-plugin/plugin.json
    skills/creative-tournament/SKILL.md
    agents/explorer.md  agents/selector.md
```

- 설정 파일에 `plugin:` 항목(저장소 기준 경로)을 더한다. 실행기는 그 폴더만 임시 폴더로 복사해 `{plugin_dir}`로 넘긴다. 에이전트는 태스크·정답을 볼 수 없다(기존 원칙 유지).
- 설정: `claude-base`(플러그인 없음), `claude-thinking`(`plugins/creative-thinking`), `claude-tournament`(`plugins/creative-tournament`).
- 사용자 설치: `/plugin marketplace add hesong0222-dev/agent-creativity-index` 후 원하는 플러그인 설치.

## 4. 도구 설계

### 4.1 생각 절차 스킬 `creative-thinking`

발동 조건(설명문): 열린 답이 있는 작업. 아이디어 내기, 글·게임·디자인 만들기, 제약이 있는 문제를 새로운 방법으로 풀기.

절차:
1. 요구사항을 한 줄씩 적는다(나중에 점검용).
2. 가장 먼저 떠오르는 뻔한 답 3개를 적고, 그것과 같은 방향은 쓰지 않는다.
3. 서로 다른 방향의 후보 3~5개를 한두 줄로 스케치한다. 방향을 만드는 수단: 먼 분야에서 빌려오기, 전제 뒤집기, 제약 하나 더하기, 관점(화자·사용자) 바꾸기.
4. 요구사항을 지키는 후보 중 가장 덜 뻔한 것을 고른다. 고른 이유를 한 줄로 적는다.
5. 완성한 뒤 1번의 요구사항을 하나씩 다시 점검한다. 어긴 것이 있으면 창의성보다 요구사항을 우선해 고친다.

중간 생각(1~4)은 결과 파일에 쓰지 않는다.

### 4.2 후보 경쟁 하네스 `creative-tournament`

- 주 에이전트가 하위 에이전트 `explorer` 3개를 동시에 띄운다. 각자 다른 관점(예: 먼 분야 빌려오기 / 전제 뒤집기 / 제약 더하기)을 받아 **완성본**을 각자의 임시 하위 폴더에 만든다. 서로의 결과는 보지 않는다.
- 하위 에이전트 `selector`가 세 완성본을 이름 없이 받아, 요구사항 위반을 먼저 걸러내고 남은 것 중 가장 독창적인 것을 고른다.
- 주 에이전트가 고른 완성본을 요구 위치로 옮기고 요구사항을 마지막으로 점검한다. 임시 폴더는 지운다.
- 하위 에이전트 수는 3으로 고정한다(요구가 확인되기 전에는 옵션을 만들지 않는다).

## 5. 개발·측정 절차

1. 벤치마크 확장(2장)과 플러그인 구조(3장)를 먼저 만든다. 기존 테스트가 모두 통과해야 한다.
2. 두 도구의 첫 버전을 만든다.
3. **연습 문제로만 다듬는다.** 연습 문제 12개, 문제당 2회 반복으로 스킬 없음과 비교한다. 다듬기는 도구마다 최대 3회. 연습 문제 채점은 Claude 채점기를 써도 된다(속도·비용).
4. **최종 측정은 한 번만.** 시험 문제 48개, 문제당 2회 반복, 세 설정. 채점은 **다른 계열 채점기(Codex)** 로 한다. 결과를 보고 도구를 다시 고치지 않는다. 고친다면 새 시험 문제가 필요하다.
5. 결과 보고서를 `docs/results/`에 쓰고 README에 요약을 싣는다. 성공·실패와 관계없이 있는 그대로 공개한다.

## 6. 실패 처리와 위험

| 위험 | 대응 |
|---|---|
| Codex 사용 한도·로그인 문제로 최종 채점 불가 | 최종 측정을 미루고 사용자에게 알린다. Claude 채점 결과로 성공을 선언하지 않는다 |
| 하네스가 시간 제한(900초)을 넘김 | 하네스 설정만 제한을 늘린다(예: 2400초). 소요 시간은 보고서에 그대로 나온다 |
| 하위 에이전트가 headless 실행에서 동작하지 않음 | 연습 문제 첫 실행에서 확인. 안 되면 사용자에게 보고하고 대안(한 에이전트가 순차로 3개 만들기)을 제안 |
| 스킬이 발동하지 않음 | 연습 문제 실행 기록(stdout)에서 스킬 사용 흔적을 확인. 설명문을 고친다 |
| 시험 문제 누수 | 2.2의 분리 작성. 이 세션은 시험 문제 폴더를 읽지 않는다 |

## 7. 테스트

- 실행기: 설정의 `plugin:` 폴더만 복사되는지.
- 점수: 평균 소요 시간 열, `--a/--b`로 짝을 고르는 것.
- 태스크: 축별 dev 4 / holdout 16, 새 문제 해결 태스크 12개가 기존 자동 점검 통과.
- 도구 자체는 단위 테스트 대상이 아니다. 효과는 벤치마크로 잰다.
